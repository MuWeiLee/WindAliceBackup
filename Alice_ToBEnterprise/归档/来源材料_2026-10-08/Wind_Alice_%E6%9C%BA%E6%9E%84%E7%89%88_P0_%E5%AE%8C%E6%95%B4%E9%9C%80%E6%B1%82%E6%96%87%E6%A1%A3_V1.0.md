## 0. 评审导读

### 0.1 目标

在不改变 Wind Alice 统一登录身份的前提下，让同一用户拥有个人工作空间、加入多个机构工作空间，在每次新登录会话中明确选择空间；机构由外部平台开通，机构管理员在 Wind Alice 内管理成员和席位；机构成员在授权有效期间访问机构产品能力；机构管理员可以在合规限定下查看**本机构工作空间**成员的 Chat/Work 内容。

### 0.2 已确认的 11 项决定

| ID | 决定 | 状态 |
|---|---|---|
| D01 | 一个账号可加入多个机构 | 已确认 |
| D02 | 机构成员由机构管理员在 Wind Alice 管理 | 已确认 |
| D03 | 正式加入机构即占用一个席位 | 已确认 |
| D04 | 机构管理中心位于 Wind Alice 内 | 已确认 |
| D05 | 邀请发出时预留席位；接受后转为正式占用 | 已确认 |
| D06 | 禁用成员保留席位，移除才释放 | 已确认 |
| D07 | 每次新登录会话选择工作空间 | 已确认 |
| D08 | 普通成员可主动退出，立即释放席位 | 已确认 |
| D09 | 机构管理员可查看本机构成员 Chat/Work 内容（边界与合规另行细化） | 已确认 |

| D11 | 机构到期在选择页可见但不可进入工作区 | 已确认 |

### 0.3 尚不能宣称闭环的关键决策

1. **[待决] 邀请方式和匹配规则**：邮箱、手机号或两者都支持；是否绑定邀请目标并要求验证。
2. **[待决] 邀请有效期**：建议 7 天；重复发送是否延期。
3. **[待决] 首位 Owner 初始化与占席**：建议外部平台提供身份，预留或占用购买席位；未注册时如何激活。
4. **[待决] 成员退出现有工作空间时的内容留存**：建议机构内容保留，用户个人内容不受影响；成员本人是否可以导出。
5. **[待决] 机构管理员的内容范围**：是否包含历史、已移除成员、附件、Work 中间结果、失败任务、删除内容；是否仅只读。
6. **[待决] 管理员内容可见的合规边界**：机构告知和接受、保密隔离墙、敏感数据与监管要求、审计与留存策略。
7. **[待决] Owner 转移确认流程**：建议新 Owner 接受后生效，原 Owner 降为 Admin，且二次验证。
8. **[待决] 机构授权缩容超额**：不自动踢人；新邀请被阻止，但存量成员后续怎么处理需商务规则。
9. **[待决] 机构到期后的管理操作**：到期机构管理员是否可查看只读机构信息及对账；工作区不可进入已确认。
10. **[待决] 个人/机构套餐与积分、Token、模型额度关系**：计量单位、扣费归属、超额策略。
11. **[待决] 机构存在多个同名主体 / 机构改名 / 合并与注销时的 ID 和历史关系**。
12. **[待决] P0 是否支持批量邀请**：本稿默认单个邀请为 P0，批量邀请归 P1。

## 1. 背景、目标、非目标

### 1.1 背景

Wind Alice 当前需要区分个人使用与机构授权使用，但不应通过注册多套账号来解决。机构的合同、采购、资质审核、开通和续期由其他平台处理；Wind Alice 作为实际使用入口，承接工作空间切换、机构成员维护、席位管理以及机构数据访问。

### 1.2 P0 成功标准

- 用户可用一个账号在个人空间和多个机构空间之间切换，且数据、授权、计量不串空间。
- 新登录会话必经工作空间选择；到期机构可见不可进入。
- 已开通机构可完成首位 Owner 激活、成员邀请→接受→占席→使用→禁用/恢复→退出或移除→释放席位闭环。
- 席位总量与邀请预留/正式占用可对账，并发下不超卖。
- Owner 可移交管理权，不因交接中断产生无 Owner 机构。
- 管理员在授权范围内访问本机构 Chat/Work 内容，并形成完整可追溯审计。
- 外部平台开通/暂停/续约/缩容信息能够最终一致且敏感权限变更即时生效（如停用与移除）。

### 1.3 非目标（P0 不做）

机构线上申请、认证、合同、支付、扩容购买；多部门层级、组织架构、SSO/SCIM、复杂审批、多机构数据共享、跨空间复制迁移、代理登录成员账号、以成员身份执行任务；默认不支持批量邀请与复杂内容审批。

## 2. 术语与业务实体

| 实体 | 主键（建议） | 定义 | 权威来源 |
|---|---|---|---|
| User（账号） | user_id | 自然人统一登录身份 | 统一账号中心 |
| Organization（机构） | organization_id | 已建立的机构主体 | 外部机构平台 |
| Workspace（工作空间） | workspace_id | 个人或机构的隔离边界 | Wind Alice |
| Membership（成员关系） | membership_id | user_id 与 organization_id 之间的关系、角色、状态 | Wind Alice |
| Invitation（邀请） | invitation_id | 待加入机构的受邀凭证、状态、过期信息 | Wind Alice |
| Entitlement（授权） | entitlement_id | 机构服务有效期、可用产品与席位数 | 外部授权平台 |
| SeatLedger（席位台账） | ledger_id | 席位预留、占用、释放的业务记录 | Wind Alice |
| Role（机构角色） | role | Owner/Admin/Member | Wind Alice |
| Resource（业务资源） | resource_id | Chat、Work、文件、Agent、知识库等对象 | 各业务系统，归属 workspace_id |
| AuditLog（操作审计） | audit_id | 成员、授权、内容查看等操作记录 | Wind Alice |

**关系约束：**

- 一个 User 恰有一个个人 Workspace；一个机构 P0 恰有一个机构 Workspace。
- User 可以属于多家 Organization；同一组织对同一 User 同一时刻最多一个有效 Membership。
- 一个有效机构必须且只能有一个有效 Owner（初始化/冻结等过渡态需要专门处理）。
- 一个有效 Membership 占 1 席；禁用仍占 1 席；一条有效待接受邀请预留 1 席。
- 每份内容在创建时绑定一个 workspace_id；用户切换不会改变归属。
- 机构管理员可读取的机构内容，仅限其当前有权限的 organization_id 对应 workspace_id；不得触达用户个人或其他机构空间。

## 3. 系统责任边界与接口契约

| 操作 | 外部机构/授权平台 | Wind Alice | 约束 |
|---|---|---|---|
| 建立机构主体、资质审核 | 主责 | 读取同步信息 | 不在 Alice 自助创建正式机构 |
| 合同、采购、计费、续约、扩容 | 主责 | 显示状态/跳转 | 不修改商业主数据 |
| 机构授权席位总量、到期日、产品包 | 主责 | 缓存/校验/对账 | 授权源单一 |
| 首位 Owner 身份指定 | 提供初始候选信息 [建议] | 激活/建立关系 | 需定义首次授权来源 |
| 成员邀请、禁用、启用、移除、退出 | 无 | 主责 | 必须审计 |
| 角色、Owner 转移 | 无 | 主责 | 角色敏感操作二次验证 |
| 席位预留、正式占用、回收 | 授权总额 | 使用台账 | 不能超卖 |
| 机构 Chat/Work 内容读权限 | 不参与 | 主责 | 隔离、告知、留痕 |
| 机构数据保存/销毁政策 | 合同/法务输入 | 执行 | [依赖] |

### 3.1 最少接口/事件

- `organization.created/updated/activated/suspended/expired/terminated`
- `entitlement.created/changed/renewed/reduced`
- `owner.initialized` 或在 `organization.activated` 内明确管理员身份
- 查询机构详情/可用授权/机构状态接口；支持增量推送与全量对账。
- 事件包含：组织 ID、授权版本号、事件唯一 ID、发生时间、生效时间、业务签名/鉴权信息。
- 事件去重、乱序处理、失败重试、定期对账；严重变更（停用）不能仅依赖长周期缓存。

### 3.2 不可信与不一致状态处理

- 外部已开通但 Alice 未初始化：展示同步中/联系支持，不允许假定已授权。
- Alice 认为有效而权威服务已暂停：强制重新校验并拒绝机构资源访问。
- 外部授权缺少席位数或期限：fail closed，不允许新邀请；存量访问按安全策略处理 [待决]。
- 同名机构不得以名称关联，必须使用稳定 organization_id。

## 5. P0 页面清单、字段与交互规范

### P01 工作空间选择页（每次新登录）

**进入**：身份认证成功→获得个人与所有关联机构 Workspace→展示选择页。**页面字段**：空间名称、类型、机构角色、机构服务状态、最近使用时间（可选）、是否可进入、机构 ID（后台）。**操作**：选择、进入、搜索（多个机构）、点击到期机构查看说明。**规则**：有效机构可进入；到期机构保留显示但不可进入工作区；被移除机构不显示；个人空间始终显示。**异常**：列表请求失败可重试；权限状态改变时点击再校验；无机构也展示个人选项。[已确认] 必选；[建议] 新会话而非每次刷新。

### P02 全局工作空间切换菜单

**入口**：导航中的当前空间名/头像菜单。**字段**：当前名称、全部可见空间、组织角色、状态、管理机构（管理员可见）。**操作**：直接切换到其他有效空间，失效显示说明。**规则**：切换时服务端重新校验；Chat/Work/文件列表和计量账户随空间更新；未保存输入可提醒；进行中的异步任务仍归属原空间，不允许在目标空间取到原空间成果。

### P03 机构管理概览

**可见**：Owner/Admin。**字段**：机构名称、ID、状态、服务包、有效期、Owner、授权总席位、正式占用（含禁用）、预留席位、剩余席位、超额数、正式成员总数、待接受邀请数、最近同步时间。**操作**：前往成员、邀请、内容、机构信息、扩容/续约外链（存在才展示）。**异常**：缩容超额、授权不同步、到期时显示原因。

### P04 成员列表

**可见**：Owner/Admin。**字段**：成员昵称、受保护账号标识、user_id（不在前端展示）、角色、成员状态、加入时间、最近机构活跃时间、操作。**筛选**：关键词、角色、状态；分页。**操作**：邀请、调整角色、禁用/启用、移除。**异常**：不能禁用/移除仅有的 Owner；Admin 不能操作同级/Owner；操作前二次确认；并发权限变更提示刷新。

### P05 添加成员弹窗

**字段**：邮箱/手机号（至少一种，待决）、默认 Member、邀请机构、邀请有效期、剩余可预留席位、附言（可选）。**提交校验**：机构有效、操作者正常且具邀请权、目标未在机构、无有效重复邀请、有剩余席位。**成功**：原子写入邀请和 SeatLedger 预留→发送通知；失败不应遗留孤儿席位预留。**安全**：受邀人接受前验证目标联系方式；邀请链接一次性/限时；避免泄露手机号/用户注册状态。

### P06 邀请记录

**字段**：邀请 ID（后台）、目标账号（脱敏）、角色、邀请人、时间、到期时间、状态、席位状态、最后发送结果。**操作**：取消、重发（幂等）、查看失败原因。**规则**：待接受独占预留 1 席；接受转正式占用；拒绝/过期/取消释放。**边界**：已经正式加入后的邀请不允许再取消来释放正式席位。

### P07 受邀人接受/拒绝邀请页

**入口**：站内通知、邮件/短信深链、待处理邀请中心 [建议]。**字段**：机构名称、邀请人、身份标识、角色、邀请期限、机构空间内容可由管理员读取的告知。**动作**：登录/注册→身份校验→接受或拒绝。**异常**：链接已过期、已接受、已撤销、机构到期、账号不匹配、被其他账号占用。**接受结果**：Membership 正常＋预留席位改正式，出现于下次空间选择列表；当前会话可以引导立即切换 [建议]。

### P08 角色管理 / Owner 转移弹窗

**字段**：原 Owner、新 Owner（仅正常成员）、两个账号的脱敏标识、权限变化说明、二次身份验证、确认状态/有效期。**过程建议**：原 Owner 发起→新 Owner 接受→数据库事务原子切换唯一 Owner→原 Owner 降 Admin→通知双方。**异常**：待接受期间原 Owner 不变；被指定人禁用/退出、申请超时、外部机构暂停则转移失败/暂停；记录审计。**[待决]** 是否需要外部机构负责人审批，以及 Owner 转移后的通知范围。

### P09 机构内容管理

**可见**：Owner/Admin。**字段**：Chat/Work 类型、标题、创建者、状态、创建时间、更新时间、工作空间、内容详情、关联附件/成果。**搜索**：创建者、日期、类型、标题/关键字（全文检索 [建议 P1]）。**操作**：只读查看本机构范围内内容及经授权的机构附件。**强制约束**：每次检索和详情服务端校验 role、member status、organization status、workspace_id、敏感数据策略；管理员读取必须审计；禁止任何私人空间/其他机构空间内容透出。**[待决]** 是否包括已退出成员的历史、已删除内容、工具输入输出、Work 思考中间态等，建议明确名单。

### P10 机构信息 / 服务到期说明

**字段**：机构名、ID、服务状态、授权产品、授权席位、服务期限、支持/续约入口（若有真实外链）、更新时间。**正常状态**：基础信息只读。**到期/暂停**：在登录选择可见，点击跳转只读到期说明，禁止访问业务工作区。**[待决]** 到期时 Owner/Admin 是否仍可进入只读管理视图；默认仅查看到期说明。

### P11 我的机构/账号关系

**所有用户可见**。**字段**：当前账号、个人工作空间、所属机构列表、角色、加入时间、机构状态。**操作**：查看、切换、主动退出（Admin/Member）；Owner 需要先转移。**退出弹窗**：确认立刻失去机构访问与相关授权、机构内容不迁移到个人空间，完成后释放席位。**异常**：正在执行的 Work 应中止后续机构数据调用并撤销访问凭证。

### P12 操作审计

**可见**：Owner/Admin（敏感审计可再分级 [建议]）。**字段**：event_id、时间、操作者、组织、对象、动作、前后状态摘要、结果、来源/设备（适当脱敏）、关联请求 ID。**覆盖**：邀请/取消/接受/过期、成员启禁/退出/移除、角色变化、Owner 转移、管理员内容查看、授权变化。**规则**：不可被普通管理员篡改；保留周期按合同/法规确定；支持权限审计回查。

## 6. 六条主业务链路：端到端检查

### F01 外部机构开通 → 初始化 Owner → 可使用

**前置**：外部已有 organization_id，产品授权/席位总额明确，初始 Owner 身份可识别。  
**主路径**：外部审核、开通→事件同步→创建机构 Workspace（幂等）→创建席位授权记录→建立/邀请首位 Owner→Owner 验证并激活→登录选择机构→进入机构管理。  
**异常**：未提供 Owner、首位 Owner 未注册、授权席位 0、事件重复、事件乱序、外部已开通而 Alice 初始化失败、机构重名。  
**成功验收**：一个机构只有一个机构 Workspace、有且仅有一个有效 Owner、Owner 计入机构席位，授权不被错误叠加。  
**未闭环项**：首位 Owner 的席位在激活前是预留还是正式占用；未激活机构如何显示；外部平台如何提供首次身份。

### F02 登录 → 选择 Workspace → 访问业务 → 切换

**前置**：已成功登录统一账号。  
**主路径**：读取个人与关联机构→展示选择页→用户选择→后端校验 Membership/Entitlement→建立工作空间上下文→进入 Chat/Work；用户可以从导航切换至其他空间。  
**异常**：机构到期/暂停、成员被禁用/移除、点击时状态变化、列表加载失败、目标空间无对应产品授权、多标签页同时使用不同空间。  
**成功验收**：每次新会话选择；到期机构可见不可进入；不同页面/请求不会跨空间读取、写入或计费。  
**未闭环项**：会话过期后是否重新选择、登录态共享与多标签页的工作空间上下文策略、未保存输入处理。

### F03 管理员邀请 → 预留席位 → 接受/拒绝 → 正式成员

**前置**：机构授权有效、邀请人有权限、剩余可预留席位 >=1。  
**主路径**：输入目标→校验→事务预留 1 席+创建唯一有效邀请→通知用户→登录/注册并验证身份→阅读内容管理告知→接受→事务转为正式席位及 Membership→可选引导切换。  
**拒绝/过期/取消**：邀请置终态→释放预留→通知/审计。  
**异常**：重复邀请、目标已经加入、邀请发送失败、接受瞬间机构到期、通知延迟、多个并发管理员、注册身份与邀请对象不一致。  
**成功验收**：没有重复占用/释放；成员最终状态、席位台账、邀请状态相符。  
**未闭环项**：过期天数、重发延期、邀请账户匹配策略、通知渠道与失败补偿。

### F04 成员正常 → 禁用/恢复/退出/移除

**禁用**：管理员发起→校验层级→立即撤销机构访问→Membership 禁用→仍占席→通知/审计。  
**启用**：管理员发起→校验机构授权有效、无特别限制→恢复正常→席位不变。  
**主动退出**：Member/Admin 确认→撤销机构访问→Membership 移除/退出→释放正式席位→保留机构内容→审计。  
**管理员移除**：验证权限并二次确认→同主动退出；Owner 不可直接移除。  
**异常**：重复点击、任务执行中、管理员与成员并发操作、禁用时当前在线、角色在提交前被修改。  
**成功验收**：被禁用或移除的用户即使持有旧 token，也无法继续访问机构资源。  
**未闭环项**：对正在运行 Work 的终止/保留策略；成员退出后其机构内容的搜索/可见性；禁用能否自助恢复（建议不能）。

### F05 Owner 转移 → 新 Owner 接受 → 完成

**前置**：当前 Owner 正常、有候选正常成员、机构有效。  
**主路径建议**：Owner 发起→二次身份验证→发起待接受转移单→新 Owner 验证身份并接受→原子互换角色→原 Owner 降 Admin→审计与通知。  
**异常**：候选人拒绝/超时、候选人离职禁用、两次转移竞争、原 Owner 在转移期间失权、外部机构状态变化。  
**成功验收**：机构任何时刻不会同时有两个有效 Owner，也不会在正常状态下没有 Owner。  
**未闭环项**：新 Owner 必须接受还是由原 Owner 直接指定；外部审批或救援流程；原 Owner 降级后的退出能力。

### F06 机构授权变更 → 续约/到期/暂停/缩容

**续约/扩容**：外部变更→同步版本→更新有效期/额度→前台刷新→可继续邀请。  
**到期/暂停**：按生效时间撤销机构业务访问→登录页仍显示但不允许进入→保留机构关系、席位台账、机构数据。  
**缩容**：更新总席位→计算超额→禁止新邀请（包括预留）→展示超额数→由管理员/商务处理。  
**恢复**：重新验证授权、成员状态→允许正常成员重新进入。  
**异常**：事件乱序、先到期后续约、缩容小于正式成员数、授权变更中 Work 正在运行。  
**成功验收**：无过期权限持续有效；不静默删除成员和资源；计数与权威授权一致。  
**未闭环项**：超额成员整改规则、到期时是否允许管理员只读进入机构管理、授权中断时任务结果保留期。

## 7. 状态机与席位规则

### 7.1 邀请状态

`PENDING（占预留席） → ACCEPTED（转换正式席） | DECLINED（释放） | EXPIRED（释放） | CANCELED（释放）`。各终态不可逆；重邀创建新邀请记录。通知发送失败不等于邀请业务创建失败，需明确重试或补偿。

### 7.2 成员状态

`ACTIVE ↔ DISABLED`；`ACTIVE / DISABLED → EXITED / REMOVED`。退出或移除后恢复需重新邀请，不应直接反转已移除状态。历史记录不可物理抹除。

### 7.3 席位定义

- 正式占用 = `ACTIVE + DISABLED` Membership 数量（同机构按 user_id 唯一）。
- 预留占用 = 有效 `PENDING` Invitation 数量；Owner 初始化预留须纳入同一账本 [建议]。
- 可邀请席位 = `max(0, 授权总席位－正式占用－预留占用)`；另存 `超额席位 = max(0, 正式占用＋预留占用－授权总席位)`。
- 接受邀请在同事务内进行 `reserved→occupied`；不会先释放给其他邀请抢占。
- 所有占席变更必须防并发冲突，有唯一键、幂等键和变更流水。

### 7.4 机构状态（建议）

`INITIALIZING → ACTIVE ↔ SUSPENDED / EXPIRED → ACTIVE`；`TERMINATED` 为终止态。**[待决]** `SUSPENDED` 与 `EXPIRED` 的恢复和管理只读策略是否一致。

## 8. 数据归属、安全和管理员内容可见

### 8.1 归属原则

- 个人 Workspace 产生的 Chat/Work/文件归个人空间；不能因为用户加入机构或管理员查阅而迁入机构。
- 机构 Workspace 产生的 Chat/Work/文件归该机构空间；成员退出、被禁用或离职，不随用户带走。
- 任务及工具调用必须以 `workspace_id + organization_id + user_id + entitlement` 绑定，而非仅用当前前端空间标志。
- 相同用户同时在不同标签页操作多个机构时，后端以每次请求携带且经过校验的空间上下文为准。

### 8.2 管理员内容查看（已确认的产品方向）

Owner/Admin 可通过机构管理中心按创建者/类型/时间查看**该机构 Workspace 内** Chat/Work 内容。建议默认只读，不允许修改、冒用成员、以成员身份发起工具调用。附件、任务中间过程、已移除成员历史、成员删除的记录，需要在「内容可见范围表」中逐项确认。

### 8.3 权限与合规保护

- 加入机构之前，向受邀用户清楚告知：机构管理员可以查看机构空间的 Chat/Work；用户明确确认后生效。
- 机构合同/机构管理员应清晰获知管理行为范围和审计安排。
- 不能用全机构管理员权限规避敏感数据分级授权、法定隔离墙、第三方数据许可和客户资料限制；必要时设限制可见子集及特殊审批，须法务合规确认。
- 查看动作至少记录 viewer_user_id、organization_id、target_resource_id、target_creator_id、时间、结果；敏感详情日志避免保存正文。
- 内容删除与保留期限、成员导出权、监管留存及机构停用后可访问范围需由数据治理方案决定。

### 8.4 权限校验参考

`账号登录有效 AND Membership.ACTIVE AND Organization.ACTIVE AND Workspace匹配 AND 产品/数据授权有效 AND 对象级权限通过`。对内容管理则需 `Owner/Admin + 可审计的读取操作 + 敏感数据策略通过`。

## 9. 核心异常与失败补偿矩阵

| 场景 | 预期系统处理 | 验收关注 |
|---|---|---|
| 同一账号重复邀请同机构 | 返回既有邀请或明确提示，不多占席 | 无重复预留 |
| 邀请与取消同时发生 | 原子串行化，只有一个终态 | 状态一致 |
| 同时邀请最后一个席位 | 仅一个成功 | 不超卖 |
| 邀请发送失败 | 重试/补偿，不产生孤儿预留 | 通知与台账一致 |
| 机构在接受邀请前到期 | 不建立有权限的正式成员关系；邀请后续处理规则待定 | 不越权 |
| 禁用成员仍持有效登录 token | 请求级校验拒绝机构访问 | 即时生效 |
| 成员退出时 Work 正执行 | 停止后续敏感调用并隔离原任务成果 | 无越权执行 |
| Owner 转移被拒绝或超时 | 原 Owner 保持身份，恢复可发起状态 | 始终有 Owner |
| Owner 意外失联 | 外部核验/客服救援通道 [待决] | 可恢复管理 |
| 机构席位缩容导致超额 | 显示超额，阻止新增，不随机踢人 | 不静默删号 |
| 到期机构登录 | 显示到期，不可进入业务 | 规则一致 |
| 管理员尝试查询他机构内容 | 服务端拒绝且审计 | 强隔离 |
| 外部事件重复/乱序 | 幂等＋授权版本判断＋对账 | 正确最终状态 |
| 同一用户多标签页切不同机构 | 请求级空间隔离 | 无串数据、串计量 |
| 账号注销/换绑邮箱手机号 | 成员和历史机构资源处理必须有独立流程 [待决] | 不丢权属、不误授权 |

## 11. 非功能需求（P0）

1. **安全**：服务端强隔离，权限变更即时作用于新请求，长期/异步任务重新校验；敏感操作二次校验、限制滥用与防重放。
2. **一致性**：成员状态、邀请记录与席位台账原子化；外部授权事件幂等且按版本处理；定时核对差异。
3. **可用性**：机构服务同步失败时提供明确错误和重试入口；不能以回退个人空间方式掩盖错误身份。
4. **可观测性**：追踪授权同步失败、席位超额、邀请发送失败、拒绝访问、管理员高敏感读取等指标与告警。
5. **隐私合规**：手机号/邮箱最小化展示、管理员内容读取留痕、用户明确告知、审计保留策略可配置。
6. **性能指标**：工作空间列表、切换、席位写入和内容检索的具体 SLO 需研发及业务约定 [待决]。

## 15. 依赖与交付顺序

### 15.1 关键依赖

- 外部机构平台：机构 ID、授权状态、席位总额/套餐/期限、Owner 初始化身份、事件与对账接口。
- 统一账号中心：登录身份、受邀目标验证、身份二次确认、账号注销/换绑事件。
- Chat/Work/文件服务：历史数据补全 workspace_id、数据隔离、任务停止与附件权限、查询接口。
- 合规与信息安全：机构管理告知、管理员内容查看边界、留存及审计、金融数据信息隔离与第三方许可。
- 运营与客服：首位 Owner 失联救援、机构同步异常、邀请通知失败及缩容处置。

### 15.2 建议研发拆期（全部属于 P0）

1. **A 账号和空间底座**：实体、授权同步、登录选择、空间隔离、切换。
2. **B 机构管理闭环**：Owner 初始化、成员邀请、席位台账、成员状态、角色/转移。
3. **C 内容和安全闭环**：机构 Chat/Work 可见范围、访问控制、告知和审计、执行中任务撤权。
4. **D 联调及回归**：跨平台状态变化、并发席位、缩容超额、多标签页、离职、到期、数据合规用例。

### 15.3 发布前的 Go/No-go 门槛

- 所有 P0-阻塞决策已有明确 Owner 和签署结论。
- 外部开通→激活→邀请→接受→使用→退出/移除链路端到端通过。
- 并发席位不超卖；成员权限撤销即时有效；管理员不能越界读取个人/他机构内容。
- 机构内容可见性与告知、合规限制通过法务/信息安全评审。
- 机构到期/续约/缩容和 Owner 转移至少各有成功及失败演练。
- 必备审计、告警、人工救援入口已就绪。
