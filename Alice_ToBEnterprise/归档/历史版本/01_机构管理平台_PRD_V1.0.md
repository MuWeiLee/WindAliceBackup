## 0. 决策状态与范围

本产品是面向机构 Owner/Admin 的独立控制台，用于邀请和管理成员、维护最多五级的组织架构、配置机构及组织节点的管理范围、查看成员在机构上下文中产生的内容以及查看席位和使用情况。Alice 页面提供入口。上游「后台管理系统」负责机构开通、禁用、席位额度和机构积分配置，机构管理平台只消费其结果。**已确认**

本稿覆盖完整产品能力及相关用户端联动，实施优先级见第 10 节。尚待确认的业务口径使用明确的建议值作为静态原型演示，不宣称已批准。后台管理系统的开通、计费与跨机构管理页面不在本稿设计范围。

### 0.1 术语

| 名称 | 定义 |
| --- | --- |
| 用户 User | 所有使用者的通称；以统一账号 `user_id` 识别，手机号是登录和邀请匹配方式 |
| 机构 Organization | 后台管理系统开通的组织主体，以稳定 `organization_id` 识别 |
| 组织节点 OrganizationUnit | 机构内部的树形管理单元，以稳定 `organization_unit_id` 识别；最多五级 |
| 一级架构 | 用户直接归属的最基层组织节点；不是机构树的根节点 |
| 二至五级架构 | 由一级架构沿父节点向上自动补全的祖先组织路径；不存在的层级留空 |
| 组织管理员 | 从当前机构成员中选择并被授予某组织节点数据范围的人；本人无需归属该节点，默认可查看本节点及全部下级节点，是否拥有写操作权待决 |
| 成员 Membership | 用户与某机构的归属关系；同一用户可属于多个机构 |
| 管理员 | 在某机构被授予机构管理平台管理权的人，通常为 Owner 或 Admin |
| Owner | 机构最高管理角色，由后台管理系统指定首位 Owner；后续转移规则待决 |
| Admin | 由 Owner 授权的机构管理员 |
| Member | 没有管理权限的机构成员；本文在席位语境中单独注明计数口径 |
| 个人工作区 | 用户个人上下文下的独立数据空间 |
| 机构成员工作区 | 某用户在某机构上下文中独立使用 Alice 的工作区 |
| 机构管理平台 | 管理单一机构内成员、权限、内容和使用情况的独立 Web 控制台 |
| 后台管理系统 | 管理多机构开通、禁用、授权席位和积分额度的上游系统 |

## 1. 目标、角色与问题

### 1.1 目标

1. 一个用户使用统一账号进入个人工作区或任一已加入机构的独立成员工作区，刷新、重启后保持当前上下文，主动切换后不串数据。
2. 上游开通机构并指定首位 Owner 后，Owner 可完成邀请→接受→补充资料→分配角色/权限→使用→禁用/移除的管理闭环。
3. 管理员按权限查看本机构成员的对话请求、生成素材/成果和分享链接，访问可追溯。
4. 机构管理员可看清席位与积分使用，额度变更来自后台管理系统。
5. 机构可维护最多五级、由基层向上聚合的组织树；成员只需设置一级架构，系统自动补全二至五级路径。
6. 每个组织节点均可设置管理员，管理员可查看本节点及全部下级组织的用户数、用量和使用情况。

### 1.2 用户角色

| 角色 | 主要任务 | 限制 |
| --- | --- | --- |
| Owner | 管理员授权、成员治理、权限模板、内容与使用查看 | 不可操作别的机构；不能改上游授权 |
| Admin | 在 Owner 授权范围内邀请/调整成员、查看内容 | 不可自行提升为 Owner；操作范围由机构配置 |
| 组织管理员 | 查看被授权节点及全部下级节点的成员和使用汇总 | 默认只读；不能越过授权节点查看父级或旁支组织 |
| Member | 接受邀请、使用个人及所属机构工作区 | 不能进入管理控制台，除非另获管理员权限 |
| 平台运营人员 | 在后台管理系统开通机构、配置上限与额度 | 不通过机构管理平台操作其他机构 |

### 1.3 痛点、设计节点与观察指标

| ID | 现状/风险 | 受影响角色 | 设计节点 | 指标建议 |
| --- | --- | --- | --- | --- |
| P1 | 机构成员开通与身份匹配不清 | Owner、受邀用户 | 邀请、身份验证、接受 | 邀请接受率、错误匹配数 |
| P2 | 跨个人/多机构上下文可能串数据 | 所有用户 | 空间选择与请求校验 | 跨空间访问事件数（目标 0） |
| P3 | 成员状态与席位占用难对账 | Owner、Admin | 成员管理、席位概览 | 台账差异数（目标 0） |
| P4 | 管理员缺乏机构内容可见性 | Owner、Admin | 内容管理 | 可追溯查看覆盖率 |
| P5 | 权限与后台开通职责不清 | Owner、平台运营 | 权限设置、机构信息 | 越权操作数（目标 0） |
| P6 | 成员只有自由文本部门，无法形成统一、可计算的组织归属 | Owner、Admin | 组织架构、成员归属 | 已分配一级架构成员占比、无效组织路径数 |
| P7 | 分级管理员无法按管理范围查看下属组织的用户和用量 | 组织管理员、Owner | 节点授权、组织统计 | 越权访问数（目标 0）、组织统计覆盖率 |

## 2. 对象、归属与隔离模型

```text
User
├─ PersonalWorkspace（用户唯一）
└─ Membership（每机构一条当前关系）
   ├─ Organization
   ├─ Role（Owner/Admin/Member）
   ├─ PrimaryOrganizationUnit（用户直接归属的一级架构）
   │  └─ AncestorPath（二至五级由父节点关系自动计算）
   └─ MemberWorkspace（该用户在该机构下独立）
      ├─ ChatRequest / ChatResponse
      ├─ WorkTask / GeneratedAsset
      ├─ File
      └─ ShareLink
```

```text
Organization
└─ OrganizationUnit（根层/五级）
   └─ OrganizationUnit（四级）
      └─ OrganizationUnit（三级）
         └─ OrganizationUnit（二级）
            └─ OrganizationUnit（一级/成员直接归属）
```

**已确认**：即使用户属于同一机构，各自的工作区仍独立。机构作为管理和授权边界，不自动把成员的内容汇成可由其他普通成员浏览的共享工作区。Owner/Admin 在管理平台按授权查看属于该机构的成员内容。

资源至少带 `organization_id`（个人资源为空）、`workspace_id`、`creator_user_id`；机构资源另带 `membership_id`。切换当前空间不改变既有资源归属。服务端每次访问按请求内空间上下文、成员状态、机构状态、功能授权和对象权限重新校验；不能只相信前端存储的当前空间 ID。异步任务、分享链接及积分消耗均绑定任务创建时的空间，切换后不改归属。**设计建议**

成员被移除时仅隐藏于常规列表并收回访问权，成员资料、内容与操作记录保留，不做物理删除。再次邀请时是否恢复原工作区待决；原型假设恢复原工作区，并在记录中显示再次加入事件。**已确认/待决**

### 2.1 组织架构与成员归属

- 每个机构维护一棵独立组织树，最多五级；机构之间的节点、管理员和统计数据必须隔离。**已确认**
- 层级按成员归属方向命名：一级架构是成员直接归属的最基层节点，二至五级依次向上。允许少于五级，不存在的层级在列表中留空。**设计建议，见 D10**
- 成员只保存稳定的一级架构节点 ID，二至五级名称及 ID 根据组织树自动计算，不允许在成员资料中逐级手工填写。**已确认**
- 当前版本按“一名成员在一个机构内只归属一个一级架构”设计；多组织兼职归属待决。**设计建议，见 D11**
- 成员可以不设置任何组织架构；未分配成员进入“未分配组织”视图，可正常使用机构工作区，纳入机构总人数和席位，但不纳入任何具体组织节点的用户数和组织统计。后续可由有权管理员补充或清空一级架构。**已确认**
- 组织节点至少包含：节点 ID、机构 ID、名称、父节点 ID、层级、状态、排序、管理员列表、创建及更新时间。移动节点时必须防止循环引用和超过五级。**设计建议**
- 组织节点停用或删除前必须处理成员、下级节点和管理员关系；首版不物理删除有历史数据的节点。**设计建议**

## 3. 角色、权限和功能开关

机构功能权限分两层：①机构可使用哪些 Alice 功能，受上游机构产品授权约束；②机构 Owner 对 Admin/Member 开放哪些已授权功能及管理动作。机构配置不得突破上游授权。**设计建议**

| 操作 | Owner | Admin | Member | 说明 |
| --- | :---: | :---: | :---: | --- |
| 进入本人机构成员工作区 | ✓ | ✓ | ✓ | 成员与机构均有效 |
| 查看机构概览/席位/用量 | ✓ | 可配置 | — | 机构内读权限 |
| 邀请 Member | ✓ | 可配置 | — | 待接受邀请预留席位为建议值 |
| 编辑成员补充资料 | ✓ | 可配置 | — | 不修改账号资料 |
| 禁用/启用/移除 Member | ✓ | 可配置 | — | 当前请求起失权 |
| 指定/撤销 Admin | ✓ | — | — | 不允许 Admin 同级互改 |
| 转移 Owner | 待决 | — | — | 首位 Owner 来源已确认 |
| 配置机构功能权限 | ✓ | 可配置 | — | 不可突破上游授权 |
| 查看机构成员内容 | ✓ | 可配置 | — | 仅读取授权范围 |
| 查看操作审计 | ✓ | 可配置 | — | 日志不可更改 |
| 修改机构开通/席位总数/积分额度 | — | — | — | 后台管理系统负责 |

默认 Admin 权限模板：成员查看、邀请、编辑资料、禁用/启用 Member、机构内容只读、席位与用量只读；默认不含移除、授予 Admin、权限模板修改。**设计建议，待机构确认**。功能权限首版为角色模板加按成员例外授权是否开放，见 D03。所有前端隐藏和禁用只改善交互，后端仍需拒绝越权调用。

### 3.1 组织管理员的数据范围

- 每个组织节点可配置组织管理员，具体人数上限见 D16。管理员从当前机构全部有效成员中搜索选择，可以是未分配组织的成员，也可以归属其他组织分支，不要求本人属于所管理节点。**已确认/待决**
- 默认可见范围为“本节点 + 全部下级节点”，包括成员列表、直属及汇总用户数、用量和使用情况；不可查看父级节点、旁支节点、个人工作区或其他机构数据。**已确认**
- Owner 默认拥有全机构所有节点的数据范围；机构 Admin 是否自动拥有全树范围沿用机构权限配置。组织管理员身份不自动授予机构级 Admin 角色。**设计建议**
- 同一成员管理多个节点时，可见范围取授权节点子树的并集；重复成员和用量只统计一次。**设计建议**
- 本版将组织管理员定义为只读数据权限。邀请、编辑、移动、禁用成员以及维护组织树等写操作是否可下放，见 D13。**设计建议，待决**
- 每次查询由服务端根据当前组织树和有效授权计算范围；前端传入的节点 ID 不能作为授权依据。组织移动、管理员撤销后，新请求立即按最新范围校验。**设计建议**

## 4. 核心业务流程

### F01 机构开通与 Owner 激活

后台管理系统创建机构、指定某用户为首位 Owner、设置席位及积分额度 → 机构管理平台同步机构与 Owner → Owner 登录后进入管理平台 → 查看机构状态及席位。未注册的 Owner 如何完成账号绑定、首位 Owner 是否占席为待决。同步未完成时展示「开通处理中」，不可先行赋权。机构 ID 由上游生成，不能按机构名称匹配。

### F02 邀请与接受

Owner/有权 Admin 在机构管理平台输入手机号及成员补充资料（姓名必填，邮箱、职位选填）→ 检查机构有效、号码格式、重复关系/邀请、席位 → 创建待接受邀请 → 发送通知 → 受邀用户登录并验证被邀请的手机号 → 阅读机构空间内容可由管理员查看的告知 → 接受或拒绝 → 接受后产生有效 Membership 与独立 MemberWorkspace。成员接受后按 F08 设置一级架构，不再使用自由文本“部门”字段表达组织归属。**已确认**：仅能由机构管理平台发起邀请；不是管理员添加即生效。

邀请过期天数、通知渠道、通知失败后的重试、待接受是否预占席位均未确认。原型按「7 天、预留 1 席、通知失败重试且不重复占席」演示。拒绝/过期/取消释放预留；接受把预留转为正式占用。并发争夺最后一席只允许一次成功。**设计建议**

### F03 成员维护

编辑补充资料只影响本机构记录。禁用立即拒绝该用户对该机构工作区的新请求、保留席位与历史内容；启用恢复。移除则隐藏于默认成员列表、回收机构访问并释放席位；审计及机构内容保留。禁用、移除前确认，不能禁用/移除唯一 Owner。主动退出是否支持及其席位释放方式待决。**已确认/设计建议**

### F04 上下文选择与切换

登录后列出个人和可用机构成员工作区；用户选择一个进入。Alice 页面显示当前上下文并提供切换。切换会刷新工作区数据，未提交的输入给出离开提醒；刷新、重启页面保持上次选择的工作区，但每次恢复须重新校验。多标签页各有自己的上下文，以每次请求明示的空间为准。机构/成员禁用后，当前机构请求被拒绝，用户可回到空间选择或切换到仍可用的个人空间，不能误删个人登录态。**已确认/设计建议**

### F05 内容查看与分享

机构工作区产生对话请求与回复、Work 最终成果/生成素材、分享链接时保存空间归属。管理平台提供按成员、类型、日期及标题筛选；管理员打开详情前重新校验权限并记审计。分享记录呈现链接、创建时间、创建者、内容类型和链接状态。范围仅限当前机构下成员工作区；用户个人或其他机构内容不可见。**已确认**

附件、Work 中间步骤、已删除内容、已移除成员历史、分享链接撤销权尚待决。原型展示请求正文、回复摘要、最终素材与分享记录；不展示系统提示词和模型内部过程。**演示假设**

### F06 上游授权变化

后台管理系统同步机构开通/禁用、席位上限、积分额度与用量口径。机构禁用后成员不可进入对应机构工作区，个人空间保持可用；管理平台保留状态说明与可被授权的只读信息。席位缩容出现超额时展示超额并阻止新增邀请，不自动移除存量成员。积分不足时按上游策略阻止新增消耗或显示提醒，具体规则待决。事件需版本、幂等和对账。**设计建议**

### F07 组织架构设置

Owner/有权 Admin 进入独立的「组织架构」页面 → 在可缩放、可平移的画布中新建首个节点 → 通过节点连接点新增相邻层级节点，或从已有节点中选择并建立上下级关联 → 拖动节点调整画布布局 → 系统校验同机构、单一父节点、无循环且不超过五级 → 保存后形成组织树。交互采用类似低代码工作流编排的节点画布；页面同时展示各节点的层级、直属用户数、下属汇总用户数和管理员。**已确认/设计建议**

拖动节点卡片只改变画布坐标，不改变组织关系；从连接点拖出连线并连接另一节点，或在节点菜单选择“关联已有节点”，才创建或调整上下级关系。节点支持“新增上级”“新增下级”“关联已有节点”“解除关联”，建立关系前预览受影响路径并二次确认。**设计建议**

组织节点改名只更新展示名称，不改变稳定节点 ID；调整连线关系会重新计算受影响子树全部成员的一级至五级路径和管理员可见范围。删除、停用或解除关联前必须提示受影响的成员、子节点和管理员。画布提供搜索、缩放、适应画布、自动布局、撤销/重做和未保存提示；最终保存时统一校验并提交。**设计建议**

### F08 成员组织归属

成员接受邀请并成为有效 Membership 后，可以保持“未分配组织”；Owner/有权 Admin 也可在成员详情或批量待分配视图中选择一级架构 → 系统保存一级节点 ID → 自动带出二至五级架构 → 成员列表和组织统计同步更新。后续可调整或清空一级架构，所有变更记录审计。**已确认/设计建议**

成员列表固定展示「用户名、邮箱、手机号、一级架构、二级架构、三级架构、四级架构、五级架构」，并可附加角色、状态、最近使用等现有管理字段。未设置组织的成员五级架构字段均为空，并支持“未分配组织”筛选。用户资料不重复保存祖先节点名称，导出和查询时按当时有效组织路径生成。历史用量在成员转组织后的归属口径见 D14。**已确认/待决**

### F09 组织管理员查看统计

组织管理员进入管理平台 → 系统加载其被授权节点 → 选择一个节点 → 查看本节点直属及包含全部下级的用户数、用量和使用情况 → 可继续下钻下级节点或筛选成员/时间。所有查询必须裁剪到授权子树并记录必要审计。指标定义、刷新频率和历史口径见 D15。**已确认/待决**

## 5. 席位与积分

**待决关键口径**：用户定义席位为机构开通后允许邀请的 Member 数量，但未明确 Owner/Admin 是否计入上限。为避免超卖，原型暂按所有有效成员关系（含 Owner/Admin/Member）计入席位，待接受邀请预留席位，禁用仍占席，移除释放。最终应以后台管理系统授权合同定义为准。

展示字段：总席位、已占用、待接受预留、剩余、超额。公式（原型）：`剩余=max(0,总席位-已占用-预留)`；`超额=max(0,已占用+预留-总席位)`。邀请接受是预留转占用，不出现先释放后被抢走的窗口。席位明细可追溯每次变化。

积分展示：机构额度、已消耗、剩余、更新时间，支持按成员/时间查看消耗明细。积分额度设置和具体扣减规则由后台管理系统及后续专项需求确定；原型数据仅用于示意。

### 5.1 组织维度统计

每个组织节点展示直属用户数和下属汇总用户数，并支持按节点查看用量和使用情况。汇总用户数按当前有效成员去重；未分配成员明确不进入任何节点统计。已禁用、已移除和待接受成员是否计入各指标，以及“使用情况”的活跃、功能和内容维度定义，见 D15。机构总量必须能够与成员、席位及计量台账对账。**已确认/待决**

## 7. 状态与异常规则

| 对象 | 状态 | 关键转移 |
| --- | --- | --- |
| 机构 | 初始化中、有效、禁用、到期 | 上游同步驱动；禁用/到期不可进入机构工作区 |
| 邀请 | 待接受、已接受、已拒绝、已取消、已过期 | 终态不可逆，重邀形成新记录 |
| 成员 | 正常、已禁用、已移除 | 禁用可恢复；移除为软删除并默认隐藏 |
| 分享链接 | 有效、已失效、已撤销 | 与成员状态联动规则待决 |
| 组织节点 | 有效、已停用、已归档 | 停用前处理成员和下级；有历史数据时不物理删除 |

异常必须提供可理解的原因和下一步：无席位、重复邀请、手机号身份不匹配、机构失效、权限变化、网络失败、外部授权同步延迟。敏感写操作要防重复提交；失败不得遗留孤儿预留。成员禁用/移除、机构禁用、权限收回后，应立即阻断新请求与后续敏感工具调用；已经生成的机构成果归属不变。**设计建议**

## 8. 审计、数据与安全要求

- 审计覆盖邀请、接受/拒绝、取消、成员资料修改、禁用/恢复/移除、角色与权限变更、Owner 变化、管理员内容查看、上游授权变化。日志至少记录机构、操作者、动作、对象、结果、时间与请求 ID。
- 组织相关审计覆盖节点新建、改名、移动、停用/恢复、成员一级架构变更、组织管理员授予/撤销以及组织统计访问。组织移动日志需记录变更前后父节点和受影响子树。
- 内容查看记录被查看资源和创建者，不把敏感正文写入审计摘要。机构管理员仅能查看当前有权机构的成员内容，且只读。
- 用户接受邀请前明确获知机构内内容可被有权管理员查看；告知版本和确认时间可追溯。金融数据分级与监管隔离要求由合规专项确定。
- 账号手机号变更不能仅凭旧手机号给新账号自动继承机构成员身份，需统一账号中心提供身份连续性依据。
- 非功能目标建议：权限回收对后续请求即时生效；关键写入具幂等性；上游变更按版本同步并定期对账。页面性能、审计保留期和服务等级待研发与业务确定。

## 9. 关键验收场景

| ID | 场景 | 通过标准 |
| --- | --- | --- |
| T01 | 一个账号个人+两个机构 | 可分别进入三个独立上下文，记录与积分不串用 |
| T02 | 刷新/重启当前机构工作区 | 保持当前上下文，且恢复时重新校验有效性 |
| T03 | 并发邀请最后一个席位 | 只有一个成功，无重复预留 |
| T04 | 接受/拒绝/取消邀请 | 成员状态与席位台账一致 |
| T05 | 禁用、启用、移除成员 | 新请求按最新状态处理；移除不物理删数据 |
| T06 | Admin 越权修改 Owner/其他机构 | 服务端拒绝并留痕 |
| T07 | Owner/Admin 查看本机构内容 | 能按授权查看并记录审计 |
| T08 | 查看个人/他机构内容 | 请求拒绝，不返回数据 |
| T09 | 上游机构禁用/席位缩容 | 机构不可使用或阻止新增，不误操作个人空间 |
| T10 | 多标签页不同机构 | 各次请求按所选上下文隔离 |
| T11 | 手机号换绑或重复邀请 | 不产生错误成员绑定或重复席位 |
| T12 | 创建不足五级的组织树 | 可保存；缺失层级留空，不要求补齐五级 |
| T13 | 设置或清空成员一级架构 | 设置时二至五级按当前父链自动带出；清空后成员保留机构使用权且不进入节点统计 |
| T14 | 拖拽节点与调整连线 | 拖动卡片只改变布局；调整连线才改变关系；不形成循环、不超过五级，受影响路径和权限范围同步更新 |
| T15 | 组织管理员查看本节点及下级 | 用户数、用量和使用情况按授权子树正确汇总 |
| T16 | 组织管理员访问父级、旁支或其他机构 | 服务端拒绝且不返回数据 |
| T17 | 撤销组织管理员或停用节点 | 后续请求立即按最新授权和节点状态处理并留痕 |
| T18 | 从全机构成员选择节点管理员 | 可选择未分配组织或其他分支成员；授权范围由所管节点决定，与本人组织归属无关 |

上述验收场景中含设计建议口径；待决事项确认后才能转为最终测试用例。

| 阶段 | 能力 | 发布门槛 |
