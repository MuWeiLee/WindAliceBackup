# Wind Alice 企业管理后台建设规划 V1.0

> 2026-10-13 · 规划稿。业务依据：`01_机构管理平台_PRD_V1.0.md`、`02_页面架构与交互说明_V1.0.md`、`03_待决事项与来源对照_V1.0.md`。视觉依据：`D:\万得Alice\Alice_Product_Management\05_设计框架\WindAliceWeb\Web-App\workspace内容模板库V4.html`。

## 1. 目标与定位

建设面向机构 Owner、机构 Admin 和组织节点管理员的独立管理控制台。复用 Wind Alice V4 的视觉语言、主题与通用组件状态；后台保持自己的导航和页面结构，以容纳成员宽表格、组织画布、统计和审计。Alice 用户端只承担管理入口、邀请处理和工作区切换等联动。

本规划分为两个交付层次：先做可操作、可评审的全功能前端演示，再对接身份、机构、席位、计量、内容和审计服务，形成真实管理后台。两层使用同一套页面与业务对象，避免演示稿重新设计一遍。

## 2. V4 样式的使用方法

V4 是约 3.6 MB 的单文件页面，包含全局导航、Panel、Workspace、通用卡片和个人中心等模块，也包含多轮样式覆盖及内嵌资源。建议以其现有亮暗主题、颜色、字体层级、边框、圆角、按钮、表单、空状态、反馈、图标和动效为视觉基准，整理一份后台共用组件规范。

后台主要复用的模式：

| V4 模式 | 后台应用 |
| --- | --- |
| 导航、页头与当前位置 | 独立控制台导航、机构切换、面包屑、页面操作 |
| 统计卡与概览区 | 机构概览、席位、用量、组织统计 |
| 表格、筛选、标签 | 成员、邀请、内容、用量明细、审计 |
| 侧栏、弹层、表单、提示 | 成员详情、节点配置、授权、危险操作确认 |
| 亮暗主题与交互反馈 | 全后台一致的主题与操作状态 |

组织画布属于新增页面模式，需要沿用 V4 的视觉令牌设计节点、连线、工具栏与右侧配置面板。画布应占据足够空间；成员表格允许页面内横向滚动。V4 的 AI 输入区属于用户工作台语境，后台是否需要 AI 管理助手可在后续单独评审。

## 3. 页面范围与优先级

| 阶段 | 页面/能力 | 完成标准 |
| --- | --- | --- |
| P0-A 底座 | 登录与机构选择、管理后台布局、主题、角色/数据范围、机构概览 | 可切换机构，数据及页面权限随机构和角色同步变化 |
| P0-B 成员与组织 | 成员列表/详情、邀请/接受、成员状态、一级组织归属、拖拽式组织画布、节点管理员 | 完成邀请到成员使用闭环；未分配成员可用；组织最多五级且路径自动补全 |
| P0-C 治理与观察 | 组织统计、角色与功能权限、内容管理、席位与积分、操作审计、机构信息 | 节点管理员仅见授权子树；组织和机构台账可对账；敏感查看可追溯 |
| P1 扩展 | 批量邀请/归属、复杂角色例外、导出及其他已列入 PRD 的扩展 | 逐项单独评审 |

后台一级导航建议为：概览、成员管理、组织架构、内容管理、权限设置、使用与额度、操作审计、机构信息。“组织统计”作为组织架构的二级页或节点视图；最终位置通过首轮页面走查确定。

## 4. 核心交互闭环

### 成员加入

有权管理员创建邀请 → 预留席位 → 用户验证身份并接受 → 成员关系与独立工作区生效 → 可保持未分配组织，或由有权管理员设置一级架构 → 系统补全二至五级 → 成员和席位列表更新。拒绝、过期、取消和并发抢占最后席位均需给出结果并保持台账一致。

### 组织画布

新建节点 → 通过“＋”新增上级/下级，或关联已有节点 → 拖动卡片调整位置、拖动连接点调整关系 → 预览受影响成员路径、管理员范围和统计 → 校验单父节点、无循环、最多五级、同机构 → 保存并留下审计。离开未保存画布时提示；服务端版本冲突时保留草稿并提供重载/重新应用路径。

### 节点管理员

在节点侧栏从全机构有效成员搜索候选人，候选人可以未分配组织或属于其他分支 → 授权生效 → 管理员可查看该节点和全部下级的成员数、用量和使用情况 → 撤销后新请求立即失权。其本人组织归属不决定管理范围。

### 治理与用量

机构 Owner/Admin 按自身权限查看机构数据，节点管理员按授权子树查看；内容、成员、统计与导出使用同一权限口径。席位及积分从上游获得机构级总量，组织级统计由成员归属和计量记录聚合；未分配成员只进入机构总量，不进入任何具体节点的统计。

## 5. 实施顺序

1. **冻结业务口径和视觉基准。** 整理 PRD 中会影响数据模型与权限的待决项，形成数据字典与权限矩阵；从 V4 提取亮暗主题、组件状态及页面示例，形成后台组件清单。重点确认五级命名、历史用量归属、统计指标、组织管理员写权限和节点停用规则。
2. **建立共享底座。** 建立后台项目结构、路由、机构上下文、角色与节点数据范围、主题切换、表格/表单/侧栏/确认框等组件。前端演示先接统一的模拟数据接口，使后续真实服务可替换。
3. **先完成高风险纵向样板。** 选“组织画布 → 选择节点管理员 → 设置成员一级架构 → 查看节点统计”做完整样板。它同时验证视觉、数据模型、权限与统计关系。
4. **补齐 P0 页面。** 按成员与邀请、概览与席位、内容与权限、审计与机构信息的依赖顺序补全所有页面和状态。
5. **接入真实服务。** 分别对接统一账号与邀请、机构/席位/积分同步、成员工作区、内容查询、计量和审计；服务端落实每次请求的机构及节点范围校验。
6. **端到端验收。** 使用 PRD 的 T01—T18 场景走查，增加画布未保存、非法连线、并发编辑、组织移动、权限撤销、未分配成员和跨机构访问场景；对照 V4 检查亮暗主题和主要组件。

建议每个阶段都交付可浏览页面、更新后的设计记录和通过/未通过的验收清单。前端演示的“保存”只改变演示数据时必须明确提示；真实发布以服务端授权、台账和审计通过为准。

## 6. 首轮页面样板

建议先做四个页面用于确定风格与架构：

1. **机构概览：** 验证后台布局、导航、机构切换、统计卡、亮暗主题。
2. **成员管理：** 验证八个固定字段、宽表格、未分配成员、筛选与详情。
3. **组织架构画布：** 验证节点、连线、拖拽、右侧配置、管理员选择、保存和错误反馈。
4. **组织统计：** 验证节点管理员可见范围、下钻和用户数/用量口径。

这四页通过评审后再批量扩展其余页面，避免整体完成后才发现 V4 样式与后台密度不匹配。

## 7. 当前差距与待决点

- 现有 `原型/index.html` 是静态演示页，仍使用旧的自由文本部门模型；需要按新的组织节点对象和管理员授权重做相关页面与状态。
- V4 是用户工作区模板，后台使用其视觉语言和可复用组件，页面布局需适配管理任务。计划不修改原 V4 文件。
- PRD 的 D01—D11、D13—D16 仍含待决业务口径；其中组织层级、管理员权限和计量口径应在真实服务开发前定稿。前端评审可使用明确标记的演示假设。
- 前端可操作不等于真实权限生效。机构隔离、节点数据范围、席位原子占用、内容访问和审计必须由服务端完成验收。
