# Wind Alice 企业管理系统与机构工作台｜产品边界和术语

> 状态：术语与产品边界已确认；具体业务规则中的未定部分单独标注。更新：2026-10-13。  
> 本文作为本目录的术语口径。[亮色原型](../历史原型/历史_组织节点亮色原型.html)只覆盖机构工作台，不是企业管理系统原型；[V1.3 需求](10_企业管理后台_当前需求_V1.3.md)为历史快照，新增席位与节点权限规则见[原型变更决策](15_机构工作台_席位与节点权限原型决策.md)。

## 一、术语

| 名词 | 定义 | 范围提示 |
| --- | --- | --- |
| 企业管理系统 | Wind Alice 管理入驻企业的多企业管理平台，负责创建企业、设置企业 Owner、设置企业席位和管理企业订单。 | 面向 Wind Alice 的多企业运营管理；机构 Owner 不是该系统的跨企业管理员。 |
| 机构工作台 | 某一个机构对内的管理平台。该机构的 Owner 和获授权的 Admin 可进入，按各自范围查看成员、管理组织架构、分配组织资源、开通功能和查看使用情况。 | 一次只管理一个机构的数据，不负责创建其他企业、设置其他企业的 Owner 或管理企业订单。 |
| Owner | 机构的负责人，拥有该机构工作台的最高管理权限。 | Owner 属于某一机构；由企业管理系统为该企业设置。 |
| Admin | 机构中某个组织节点的管理员。Owner 从该节点及其下级节点的有效成员中选定人员并授予管理节点；Admin 的管理范围是获授权节点及其下级。 | 没有独立的“机构级 Admin”角色；Admin 的直接归属节点不必是被授权节点，但必须位于其子树内。Owner 默认管理所有节点。 |
| 成员 | 属于机构的用户。一个用户最多归属一个机构；可以暂不归属该机构内的具体组织节点。 | 用户可在个人空间与其唯一加入的机构空间之间切换，不存在多个机构之间切换。 |
| 组织节点 | 机构工作台内最多五级组织架构中的一个节点。成员可直接归属任一层级节点，上级节点汇总下级数据。 | 组织节点不是独立机构，也不是企业管理系统中的“企业”。 |
| 功能 | 可单独开通的某一个技能、某一个连接器、某一个专家，或某个功能模块。 | Owner 向节点下放功能；节点 Admin 在获授权范围内调整本节点或子节点可用的功能。新增具体项默认关闭。 |

## 二、两个产品的职责

| 业务动作 | 企业管理系统 | 机构工作台 |
| --- | --- | --- |
| 创建入驻企业、设置该企业 Owner | 负责 | 接收并展示当前机构和 Owner 信息 |
| 设置企业总席位、管理企业订单 | 负责 | 展示获配席位，并在机构组织节点间分配和使用 |
| 建立机构内部五级组织、维护成员 | 不作为机构内部日常操作入口 | Owner 管理全机构；Admin 在获授权节点及下级范围内管理成员 |
| 指定节点 Admin | 不作为机构内部日常操作入口 | Owner 从该节点及下级的有效成员中指定，并设置管理节点 |
| 下放与调整具体功能 | 跨企业能力供给边界由企业管理系统或上游决定 `[待确认]` | Owner 向节点下放；节点 Admin 在其管理范围内调整可用状态 |
| 查看机构用量和内容记录 | 跨企业统计与可见范围 `[待确认]` | 按 Owner 全机构、Admin 授权子树的范围查看；记录详情和隐私边界 `[待确认]` |

机构工作台中的席位分配不得改变企业管理系统设定的企业总席位；企业订单的创建、变更和结算不在机构工作台完成。机构工作台不能因节点 Admin 获得下级节点管理范围，就授予其其他企业的数据访问权。

## 三、身份、归属与切换

Owner 和 Admin 是机构工作台的管理身份，成员是机构用户身份。Admin 从获授权节点及其下级的有效成员中产生；用户直接归属的组织节点，与其被授权管理的节点是两项独立关系。Owner 设置或撤销节点 Admin 授权，不改变该成员的直接组织归属。Owner 默认拥有所有节点的管理权。

一个用户最多加入一个机构，但可同时拥有个人空间。用户在个人空间和唯一的机构空间之间切换时无需退出登录；机构工作台只呈现当前机构的管理内容。机构工作台原型左下角的 Owner/Admin 视角切换仅用于评审，不代表正式产品可任意切换身份。

## 四、功能与席位的传递路径

```text
企业管理系统：创建企业 → 设置 Owner、企业总席位、订单
                                  ↓
机构工作台：Owner 建组织节点 → 分配节点席位 → 指定节点 Admin → 下放具体功能
                                  ↓
机构工作台：节点 Admin 管理授权子树的成员、向子节点分配席位并调整可用功能
                                  ↓
成员在机构空间使用 → 用量、内容生成、分享和下载记录回到机构工作台
```

功能按具体项目控制。例如微信连接器与飞书连接器是两个开通项；某个功能模块也可作为开通项。Owner 下放与 Admin 调整的关系已确认，具体的上级关闭、子节点状态及既有成员生效规则 `[待确认]`，不能用界面开关状态自行推定。

## 五、仍待确认的产品边界

- “入驻企业”与“机构”是否始终一一对应，正式界面统一使用哪个名称。
- 企业管理系统由哪些 Wind Alice 内部角色操作，以及这些角色能否查看企业成员、内容详情。
- 企业管理系统设置企业总席位和订单后，机构工作台中席位增减的生效、回收与合同周期口径。
- 企业可用功能目录由哪里设定；Owner 下放功能后是立即可用，还是仅授予节点 Admin 开启资格；上级关闭时子节点是否可开启。
- 文件资料是否按具体文件、文件夹、资料库或功能模块控制。
- Admin 可查看授权子树成员的用量、内容生成、分享和下载记录；历史内容随成员跨节点移动后的归属口径、敏感内容展示方式，以及操作日志是否向 Admin 开放仍待确认。

上述未定项不影响两个产品的命名与职责划分；产品页面和后续 PRD 应分别编写，不把企业订单、跨企业管理入口放进机构工作台原型。
