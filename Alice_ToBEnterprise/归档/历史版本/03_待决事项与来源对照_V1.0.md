# 来源对照与待决事项 V1.0

## 1. 决策优先级

本轮用户直接确认的规则高于两份历史需求稿。历史两稿之间冲突时，不推断为已确认；本版仅提出设计建议供评审。来源文件保存在 `归档/来源材料_2026-10-08/`。

| 本轮规则 | 设计落点 |
| --- | --- |
| 用户是所有使用者的代称；成员是用户在机构下的关系 | PRD 术语、Membership 对象 |
| 管理员为获得机构管理平台管理权的人 | Owner/Admin 管理入口与权限校验 |
| 机构管理平台是独立控制台，Alice 内有入口 | 独立导航和跳转路径 |
| 后台管理系统负责开通/禁用机构、席位额度和积分配置；指定首位 Owner | 上下游边界与同步 |
| 仅机构管理平台可邀请成员，并补充机构内资料 | 邀请流程和成员资料 |
| 个人与机构工作区独立，登录后可切换，刷新重启保持 | 上下文选择、持久化、服务端再校验 |
| Owner/Admin/Member 三级角色，Owner 最高 | 权限矩阵 |
| 各机构可自设功能权限 | 权限设置，受上游授权约束 |
| 席位是开通后允许邀请的 Member 数量 | 容量管理，具体计数对象待决 |
| 可查看成员对话请求、生成素材和分享链接 | 内容管理的三种类型 |
| 成员删除仅隐藏，不物理删除 | 移除状态和历史保留 |
| 机构下每名用户仍有独立工作区 | `MemberWorkspace`，管理查看跨成员汇总 |
| 机构支持最多五级、由基层向上聚合的组织架构 | 新增组织节点模型与独立组织架构页面 |
| 用户只设置一级架构，后续层级自动带入 | 成员保存一级节点 ID，二至五级按父链计算 |
| 每个组织节点均可设置管理员 | 节点级管理员授权 |
| 组织管理员可看下方组织的用户数、用量和使用情况 | 本节点及全部下级的数据范围与组织统计 |
| 组织架构使用类似低代码平台的拖拽式节点画布 | 画布、节点卡片、连接点、连线及右侧配置面板 |
| 成员可以不设置组织架构 | 未分配成员可正常使用机构工作区，不进入具体节点统计 |
| 节点管理员从机构成员中选择，不要求本人属于该节点 | 管理员候选范围为全机构有效成员，授权范围与本人归属解耦 |

## 2. 两份历史稿中的冲突处理

| 议题 | P0 完整稿 | 机构空间与成员管理稿 | 本版处理 |
| --- | --- | --- | --- |
| 管理入口 | Alice 内管理中心 | 独立后台 | 按本轮结论：独立控制台 + Alice 入口 |
| 加入机构 | 邀请并接受 | 管理员添加后生效 | 按本轮结论：邀请；接受及身份验证为设计建议 |
| 登录后切换 | 支持 | 必须重登 | 按本轮结论：支持切换并持久化 |
| 工作区模型 | 每机构一个 Workspace | 每机构一个机构空间 | 按本轮结论：每个成员在每机构有独立工作区 |
| 角色 | Owner/Admin/Member | 管理员/成员 | 按本轮结论：三级 |
| 内容范围 | Chat/Work 与可能附件 | 分享记录 | 按本轮结论：对话请求、生成素材、分享链接 |
| 成员删除 | 状态终止、留历史 | 列表隐藏、软删除 | 本轮确认仅隐藏、不物理删除 |
| 席位 | 成员正式占用，邀请预留 | 未定义 | 席位上限已确认，具体计数待决 |

## 3. 待决问题与当前演示假设

| ID | 需谁决策 | 要确定的规则 | 原型演示假设 |
| --- | --- | --- | --- |
| D01 | 商业/后台/产品 | Owner、Admin、Member 是否均计入席位；待接受是否预留 | 全部计入，待接受预留 |
| D02 | 产品/数据治理 | 已移除用户再次加入时是否回到原工作区 | 恢复原工作区 |
| D03 | 产品/机构客户 | 按角色配置还是支持单人成员例外 | 角色模板 |
| D04 | 合规/产品 | 内容历史、附件、已移除成员、中间过程的可见范围 | 最终内容和历史可见，中间过程不可见 |
| D05 | 产品/后台 | Owner 转移与失联救援 | 本版不开放操作原型，仅描述候选流程 |
| D06 | 产品 | 主动退出与失效分享链接 | 本版不开放主动退出，链接状态单独记录 |
| D07 | 产品/通知服务 | 邀请有效期、渠道与重试 | 7 天，失败可重试 |
| D08 | 商业/计量系统 | 积分扣减与超额处理 | 只展示额度与消耗 |
| D09 | 产品/运营 | 机构禁用/到期时管理平台可看什么 | 仅机构状态说明 |
| D10 | 产品/机构客户 | 五级是否为最大深度；一级是否指成员直接归属的最基层 | 最多五级；一级为最基层 |
| D11 | 产品/机构客户 | 成员是否允许同时归属多个一级组织 | 一个机构内只归属一个一级组织 |
| D13 | 产品/安全 | 组织管理员是只读还是可管理下属成员 | P0 只读，写操作仍由 Owner/有权 Admin 执行 |
| D14 | 产品/数据 | 成员转组织后的历史用量归属 | 历史按发生时归属，新用量进入新组织 |
| D15 | 产品/数据/计量系统 | 用户数、用量、使用情况的指标定义和刷新频率 | 有组织归属的有效成员去重，未分配成员排除；用量按计量台账；展示活跃和功能使用 |
| D16 | 产品/机构客户 | 单节点允许的管理员数量及上级授权继承 | 候选人为全机构有效成员；暂按可多人、上级可见下级、不反向继承 |

这些假设为需求和后续演示流程提供完整样例，不能视为业务方已经批准。D10、D11、D13—D16 会影响组织数据模型、权限规则、统计口径和页面操作，建议在研发详细设计与原型更新前确认。

## 4. 本轮新增需求的边界

### 已纳入

- 机构内最多五级的组织树及独立设置页面。
- 采用类似低代码工作流的节点画布，通过拖拽、连线、新增或关联已有节点维护组织关系。
- 从最基层向上建立、聚合组织关系。
- 成员只设置一级架构，二至五级自动补全。
- 成员可以不设置任何组织架构，并正常使用机构工作区。
- 成员列表展示用户名、邮箱、手机号和一级至五级架构。
- 每个组织节点可从全机构有效成员中选择管理员，不要求管理员本人归属该节点。
- 组织管理员查看本节点及全部下级的用户数、用量和使用情况。
- 组织变更、成员归属变更和管理员授权的审计。

### 本轮不直接确认

- 用户自助选择或修改所属组织；当前仅有权管理员可设置或清空。
- 一名成员同时归属多个一级组织。
- 组织管理员直接邀请、编辑、移动、禁用下属成员。
- 跨机构组织树、虚线汇报关系和矩阵式组织。
- 历史组织快照、统计指标公式及刷新时效的最终合同。
