# 企业管理后台｜会议新增需求与待确认

> 来源：2026-10-13 会议讨论，由用户提供的 12 条纪要及后续确认整理。状态：部分规则已确认，其余仍待确认。  
> 本文讨论的机构内部管理能力属于[机构工作台](14_产品边界与术语定义.md)；创建企业、设置企业 Owner、企业总席位及订单属于企业管理系统。[机构工作台 V1.3](10_企业管理后台_当前需求_V1.3.md) 是历史快照。[亮色原型](../历史原型/历史_组织节点亮色原型.html)已演示节点席位、逐项功能开通和授权范围内的内容查看，但合同、积分结算及真实数据采集仍未实现，见[原型变更决策](15_机构工作台_席位与节点权限原型决策.md)。

## 一、需求结论

| 编号 | 会议内容整理 | 状态与边界 |
| --- | --- | --- |
| M01 | Wind Alice 账号体系要求与 Alice Market 独立、不一致。 | 产品目标已提出；账号隔离的具体对象与方式需找 liwei 确认，不能据此断定目前系统已独立。 |
| M02 | 技能、连接器、专家、文件资料分别管理；新增项默认不开。 | 已确认“功能”可指某个技能、连接器、专家或功能模块。Owner 向节点下放；节点 Admin 在管理的节点及子节点范围内调整可用状态。技能、连接器、专家按具体内容项分别控制，例如微信连接器、飞书连接器、公司分析技能；新增具体内容项默认关闭。文件资料的控制粒度、上下级开关关系待确认。 |
| M03 | 组织节点需有权限管理和席位配额；创建时设置席位数量。 | 企业总席位由企业管理系统设置；机构工作台在本机构组织节点内分配。节点配额与总席位、已有成员占用的关系待细化。 |
| M04 | 一般用户登录后可选择个人或机构，进入后切换无需退出登录。 | 已确认同一账号可在个人空间与其唯一加入的机构空间之间免退出切换；界面需显式标识当前空间，个人与机构数据不能串用。 |
| M05 | 一个用户仅可存在于一个机构；管理后台添加用户时检查是否已属于其他机构。 | 已确认一个账号最多加入一个机构，个人空间不计为第二个机构。添加成员时应校验其现有机构关系；重复关系、待接受邀请和跨机构迁移的处理待细化。 |
| M06 | Owner 向 Admin 所管理节点分配席位，Admin 可继续向下级节点分配。 | 这里的 Admin 均指节点管理员，不存在单独的机构级 Admin。席位采用本机构节点间逐级分配；每级可分配数、已占用数和未分配数须可追溯，不得重复计算。 |
| M07 | 席位增加或减少以机构合同起始时间为基准。 | “以起始时间为基准”具体指生效日、合同周期、按期结算还是其他规则，待业务确认。 |
| M08 | 修改采用继承模式，用户继承积分剩余数。 | 已确认触发场景是席位转给新用户：新用户继承该席位的剩余积分。余额是席位维度的剩余额度，不等于原用户所有积分或历史使用记录；每日上限、加油包及转移生效时间仍待细化。 |
| M09 | 需要每日积分上限，以便计算席位继承。 | 上限所属层级、重置时间、未用完是否结转，以及与总积分余额的关系待确认。 |
| M10 | 加油包积分需设置过期时间。 | 应记录每笔加油包的有效期；消费顺序、过期余额及退款/撤销处理待确认。 |
| M11 | 对话产物的分享、下载行为需要记录到管理平台。 | 新增分享与下载事件，不应只存产物本身；记录字段与可见范围待确定。 |
| M12 | 对话记录、执行记录需要记录到管理平台。 | 内容页范围由现有的演示“对话请求、生成素材、分享记录”扩展为对话与执行记录；详情可见范围、隐私边界待确定。 |

## 二、关联场景与角色

| 角色 | 本轮新增任务 | 当前痛点或风险 |
| --- | --- | --- |
| 一般用户 | 登录后进入个人或唯一机构空间，并免退出切换 | 空间和内容归属不清时，可能把个人与机构数据混用 |
| 机构 Owner | 管理本机构成员、组织节点、具体功能开通和机构获配席位；向节点 Admin 所管理的节点分配席位 | 缺少节点配额和合同口径，无法判断可分配量；不管理其他企业的订单 |
| 节点 Admin | 在授权子树内继续向下分配席位、调整可用功能并管理成员 | 现行原型只有成员管理，无席位下拨、功能开通与余额展示 |
| 机构运营/审计人员 | 核对积分、分享下载、对话与执行记录 | 现行记录覆盖不足，难以追溯资源使用与流转 |
| 合同与账号系统负责人 | 确认账号独立、合同周期和总席位来源 | 外部口径未定会影响后台规则及数据对账 |

## 三、业务流程草图

以下仅表达会议提出的动作与依赖，步骤间的正式生效条件仍待确认：

```text
账号登录 → 选择个人 / 唯一机构空间 → 使用中无需退出切换
             │
企业管理系统设置企业总席位 → 机构工作台 Owner 设置节点席位 → 节点 Admin 向下级分配 → 添加成员时校验机构唯一性与可用席位
             │
席位转给新用户 → 新用户继承该席位剩余积分
             │
Owner 下放具体功能 → 节点 Admin 调整节点或子节点的可用功能（技能 / 连接器 / 专家 / 功能模块；文件资料粒度待定） → 成员使用 → 每日积分上限与加油包有效期
             │
对话 / 执行 → 产物分享 / 下载 → 管理平台记录与查询
```

席位转交已确定为积分继承的触发场景；单纯调整组织归属、修改节点配额是否触发积分变化，尚未确认，不应自动套用席位转交规则。

## 四、问题与初步优先级

优先级是产品分析建议，并非会议确认的排期或交付承诺。

| 问题 | 影响的流程 | 建议优先级 | 可观察指标（目标值待定） |
| --- | --- | --- | --- |
| 账号/机构关系不唯一、空间切换归属不清 | 登录、添加成员、访问内容 | 高 | 跨机构重复添加拦截数；空间归属错误数 |
| 节点席位无逐级台账和合同时间口径 | 合同开通、Owner/Admin 分配、成员添加 | 高 | 总席位与节点分配差异数；超配/超占事件数 |
| 积分继承与每日上限口径未定 | 席位调整、成员使用、积分结算 | 高 | 余额对账差异数；超过每日上限事件数 |
| 四种能力未独立管控 | 机构或节点授权、成员使用 | 中 | 未授权能力调用次数 |
| 分享、下载、对话与执行记录不完整 | 管理查询、审计追溯 | 中 | 应记录事件与实际记录的差异数 |
| 加油包过期规则不明 | 积分消费与余额展示 | 中 | 过期余额对账差异数 |

## 五、与当前设计的差异

- V1.3 把席位与积分额度视为上游提供、工作台主要查看；本次会议提出机构 Owner 和节点 Admin 逐级配置组织节点席位，因此需要新增席位分配与对账流程，而非只加统计卡。企业总席位和订单归企业管理系统。
- V1.3 的账号视角切换只用于原型评审；本次会议提出真实产品的“个人 / 机构空间”免退出切换，两者不能混同。
- 早期历史 PRD 曾允许同一账号加入多个机构；本次会议提出最多一个机构，正式规则确认后应以新口径覆盖历史材料。
- 现有原型可按节点 Admin 范围查看内容生成、分享和下载的本地演示记录，尚无真实对话、执行、分享或下载事件采集。

## 六、待确认与责任

| 问题 | 需要的决定 | 建议确认方 |
| --- | --- | --- |
| Wind Alice 与 Alice Market 的账号独立边界 | 登录身份、账号 ID、手机号、用户资料和机构关系分别是否共用 | liwei；账号系统负责人 |
| 一个用户仅在一个机构 | 已确认可同时拥有个人空间；已有多机构用户如何处理，添加时遇到重复机构如何反馈、待接受邀请是否占用唯一名额 | 产品与账号系统 |
| “新增项默认不开” | 技能、连接器、专家已明确按具体内容项独立控制且新项默认关闭；文件资料的控制粒度，以及机构、节点、成员间是否继承权限 | 产品与能力负责人 |
| 席位分配 | 机构总池、节点保留量、Admin 可分配范围；Owner/Admin 是否占席；缩容和超配处理 | 产品、合同与结算负责人 |
| 合同起始时间 | 增减席位的生效与结算基准、合同续期、跨期调整 | 合同与结算负责人 |
| 积分继承 | 已确认席位转给新用户时继承该席位剩余积分；转交生效时间、当日已用量与每日上限、加油包及历史记录的处理 | 产品与计量负责人 |
| 每日积分上限 | 设置层级、重置时区、结转规则、与加油包积分的扣减顺序 | 产品与计量负责人 |
| 加油包过期 | 有效期起点、到期时间、消费顺序、到期通知及余额处置 | 产品与结算负责人 |
| 内容与事件记录 | 对话/执行/分享/下载的字段、留存期限、敏感数据与 Admin 可见范围 | 产品、安全与业务负责人 |

在这些口径确定前，原型不应展示虚构的席位余额、积分继承结果或真实账号切换结果。
