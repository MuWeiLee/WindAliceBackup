## 一、产品定位与范围

为单个机构“万得”建立独立的亮色机构工作台。只有两类后台管理身份：机构 Owner 是该机构负责人，管理本机构的组织和授权；Admin 是由 Owner 指定到一个或多个组织节点的节点管理员，查看该节点及下级的成员和用量，并管理范围内的普通成员。不另设全机构 Admin。

本轮原型包含 7 个页面：概览、成员、组织架构、使用情况、内容、管理员、操作日志。创建企业、设置企业 Owner、企业总席位和企业订单属于企业管理系统，不在机构工作台原型中完成。真实账号创建与加入、组织内席位分配、积分规则和实际用量计量也尚未在本轮原型中实现；其中组织内席位分配已由后续会议提出为机构工作台需求。

### 页面框架

左侧固定区域自上而下为当前机构“万得”、按权限显示的功能菜单、用户名称及更多入口。当前机构与组织树节点是不同概念；单机构场景仅展示机构，不提供无意义的切换控件。右侧顶栏左边是页面路径，右边是当前页面可用的核心操作，例如“添加成员”“新建节点”；内容区保留页面标题和业务内容，不重复顶栏操作。左下角用户菜单提供账号信息与权限范围；原型中的演示账号切换收在该菜单内，正式产品不提供任意身份切换。

## 二、角色与数据范围

| 能力 | Owner | Admin |
| --- | --- | --- |
| 查看机构概览、全机构成员、组织、用量、内容和操作日志 | 可 | 不可 |
| 查看被授权节点及所有下级节点的成员、组织和用量 | 可 | 可，仅限授权范围 |
| 新增、查询、编辑、禁用、移除和恢复普通成员 | 可，全机构 | 可，仅限授权范围 |
| 创建、编辑、调整、删除组织节点 | 可 | 不可 |
| 设置或撤销 Admin 的节点授权 | 可 | 不可 |

Owner 是本机构工作台的最高管理权限，不是企业管理系统的跨企业管理员；唯一 Owner 不可被移除。Owner 可从全机构有效普通成员中选择 Admin，不要求候选人本人归属被管理节点，也可选择未分配组织的成员。授权与被授权人的自身组织归属相互独立。同一人获多个节点授权时，管理范围是这些节点及下级的并集。

Admin 只能在管理范围内添加普通成员，查询、编辑、禁用、软移除或恢复范围内普通成员；不能操作 Owner、其他 Admin、未分配组织成员或其他分支成员。Admin 编辑成员归属时，目标节点也必须在其管理范围内，不能把成员移出授权范围或设为未分配。Admin 可查看授权范围内的组织结构和用量，但不能修改组织、设置 Admin、查看全机构概览、内容或操作日志。普通成员若无 Admin 授权，不进入本后台。

成员“移除”是软移除，保留历史和操作记录；禁用与移除的具体账号停用效果须与统一账号系统对接后确认。原型中的账号切换仅用于评审视角差异，不能当作真实权限控制。

## 三、组织与成员模型

### 3.1 组织节点

- 机构下可设置多棵组织树，最多五级，节点只有一个上级，可从基层逐层向上聚合。
- 拥有者在组织画布中新建顶层或下级节点；画布卡片可拖动调整展示位置。更改组织关系通过节点详情中的“上级节点”完成，需拦截循环关系和超过五级的层级。
- 每个节点可直接拥有成员，也可有下级节点。节点显示“直属成员”及“下级成员”；节点总人数为两者之和。节点用量按该节点及下级成员聚合。
- 新建下级节点，只改变树形关系，不迁移原节点的直属成员。将某节点改挂到其他上级时，成员仍直接归属原节点，但其上级路径和上层统计随树形关系更新。
- 节点已有直属成员或下级节点时，不允许直接删除；先处理成员归属或下级关系。删除、迁移后的历史记录保留方式待服务端设计确定。

### 3.2 成员归属与列表

- 一个成员可直接归属任意层级的一个组织节点，也可以暂不归属任何节点；不要求只能选择叶子节点。
- Owner 从“成员”页添加成员时，归属组织可留空；Admin 添加时必须选择授权范围内的节点。从某节点的成员区添加时，归属固定为当前节点；后续可由有权人员在成员编辑中调整。
- 成员列表展示：用户名、邮箱、手机号、归属组织、上级组织、第三层组织、第四层组织、第五层组织，以及身份/状态和可用操作。
- 表格中第一列组织层级始终是该成员**直接归属的节点**，后续各列沿父链向上计算；不足五层留空。组织画布中某节点因新增下级而由“第一级”变为“第二级”，不会改变原成员的直接归属，也不会自动将成员移入新增节点。
- 未分配组织成员计入机构总人数；不计入任何节点的 Admin 管理范围。Admin 本人的组织归属不决定其授权范围。
- 有效成员用于当前人数和用量聚合；已移除成员仍可通过成员状态筛选及历史记录追溯，不计入当前组织人数。

## 四、页面内容与关键操作

| 页面 | 本轮内容与操作 |
| --- | --- |
| 概览 | 全机构有效成员、未分配成员、组织节点、演示用量及最近操作；仅 Owner 可见。 |
| 成员 | 按关键词和状态筛选，查看五层归属路径；Owner 管理全机构普通成员，Admin 管理授权节点及下级的普通成员。 |
| 组织架构 | 画布展示节点和连接关系，定位、缩放、拖动展示位置；Owner 新建下级、调整上级、设置 Admin；选中节点后分别查看直属与下级成员，Owner/Admin 可从有权节点添加直属成员。 |
| 使用情况 | Owner 查看机构或组织范围的数据；Admin 仅查看授权范围内的人数、用量、使用中成员和人均用量。原型数值为演示数据。 |
| 内容 | Owner 只读查看本机构的对话请求、生成素材、分享记录及详情；当前仅为演示记录。 |
| 管理员 | Owner 查看 Admin 的节点授权，指定成员与节点，或撤销某项节点授权；也可在组织节点详情设置。 |
| 操作日志 | Owner 查看成员、组织、Admin 授权等变更记录；原型仅保存有限条本地演示记录。 |

## 五、关键业务流程

1. **添加成员**：Owner/Admin 填写用户名和手机号，邮箱可选。Owner 可留空归属，Admin 必须选管理范围内的节点。若从节点发起，归属固定为当前节点。
2. **调整组织**：Owner 新建节点或更改上级；保存前校验单父节点、无循环、最多五级。节点的直属成员保持归属，父链展示和汇总数据随之更新。
3. **设置 Admin**：Owner 选有效普通成员和授权节点；该成员即成为 Admin，可查看和管理本节点及下级的普通成员，并查看范围内用量。撤销某节点授权后，该节点及下级权限立即失效；若仍有其他节点授权，其 Admin 权限保留。
4. **维护成员**：Owner 可管理全机构普通成员；Admin 仅能管理授权范围内普通成员，不能修改 Owner 或其他 Admin。成员编辑不得将其移出 Admin 管理范围；角色与成员状态变更应留下操作记录。

## 六、上线边界与待确认事项

原型当前用浏览器本地数据模拟成员、用量、内容和日志；刷新后保留在当前浏览器，不与真实机构数据同步。真实上线必须在服务端完成账号认证、机构隔离、节点范围授权、审计留存与用量汇总，不能仅依赖前端隐藏按钮。

| 事项 | 当前状态 |
| --- | --- |
| 企业创建、Owner 设置、企业总席位和订单管理 | 属企业管理系统；机构工作台只接收本机构相关结果，本轮原型未对接。 |
| 成员邀请/加入、手机号验证与账号关联 | `[待确认]` 对接系统和生效流程；原型中的“添加成员”只验证页面操作。 |
| 组织内席位分配、积分额度、成员移除后额度回收 | `[待确认]` 企业总席位由企业管理系统设置；工作台内节点分配、积分和超额处理属于后续需求，尚未进入本轮原型。 |
| “用量”“使用中成员”的计量口径与更新时间 | `[待确认]` 实际数据源和统计周期；原型均为演示数据。 |
| 内容详情可见范围、敏感内容处理和操作日志保留期限 | `[待确认]` 上线前与安全、合规及业务方确定。 |
| 多人同时调整组织、删除/迁移节点的历史归属处理 | `[待确认]` 服务端并发与审计方案。 |

## 七、评审建议

先用[原型评审指南](../../原型/README.md)分别走通 Owner 与 Admin 视角；重点检查跨组织选择 Admin、授权节点及下级的成员管理、未授权分支不可见，以及新增下级节点后直属成员归属不变。其余待确认项应在真实系统设计前逐项敲定。

## 八、会议增补规则（已确认，待进入新版原型）

| 模块 | 已确认规则 | 与 V1.3 原型的关系 |
| --- | --- | --- |
| 个人与机构空间 | 同一账号可在个人空间和其唯一加入的机构空间之间免退出切换；一个账号最多加入一个机构。管理后台添加成员时，须检查该账号是否已加入其他机构。 | V1.3 左下角的“演示账号切换”仅用于评审 Owner/Admin 视角，并非真实空间切换。 |
| 具体功能项授权 | 功能可指某个技能、连接器、专家或功能模块；Owner 向节点下放，节点 Admin 在管理的节点及子节点范围内调整可用状态。技能、连接器、专家按具体项分别控制，新项默认关闭。 | V1.3 未提供逐项授权。文件资料的控制粒度、上下级开关的生效关系仍待确认。 |
| 席位转交与积分 | 席位转给新用户时，新用户继承该席位的剩余积分，不自动继承原用户的所有积分或历史记录。 | V1.3 未提供席位分配、转交和积分结算。每日上限、加油包与生效时间仍待确认。 |

会议还提出账号体系独立、节点席位逐级分配、合同时间、每日积分上限、加油包有效期及内容记录扩展等需求；详细边界与待确认项见[会议新增需求](13_会议新增需求与待确认_2026-10-13.md)。在规则与数据来源确定前，不用演示数字替代真实余额或记录。
