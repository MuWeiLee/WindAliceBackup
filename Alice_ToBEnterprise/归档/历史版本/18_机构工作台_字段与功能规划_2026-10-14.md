# 机构工作台｜字段设计与功能规划

> 状态：讨论汇总，更新于 2026-10-14。本文汇总当前确认的本期口径、已提出但尚未落地的新增需求，以及仍需决定的规则。标有 `[待确认]` 的内容不能作为已定开发规则。当前原型为单文件演示，不能代表服务端能力已经实现。

## 1. 产品定位与本期范围

企业管理系统由 Wind Alice 运营侧使用，负责创建企业、设置机构 Owner、管理企业采购席位及订阅订单。机构工作台面向单个机构，供该机构的管理人员维护成员、分配已采购席位并查询使用记录。机构工作台不能直接修改采购席位总数，也不管理其他企业的订单。

本期机构工作台以 Owner 视角设计，页面包括成员管理、席位管理、对话内容、分享链接、文件下载和积分记录。节点 Admin、组织架构、节点配额与功能开通属于此前讨论的后续方向，是否纳入本期尚未确认。普通用户可在个人空间和其唯一加入的机构空间之间切换；同一时间只归属一个机构。

## 2. 核心对象与字段

账号、机构成员关系和席位分别代表登录身份、机构内的成员身份和机构购买的使用资源。同一账号移除后重新加入机构，会创建新的成员关系；历史记录保留在旧关系下。

```text
登录账号 ──加入机构──> 机构成员关系（成员ID）
                         │
                         ├── 可绑定 0 或 1 个付费席位
                         └── 关联在该成员关系期间产生的使用记录
订阅订单 ──提供──> 付费席位（席位编号） ──当前绑定──> 机构成员关系
```

### 2.1 账号与成员

| 字段 | 定义与用途 | 规则 |
| --- | --- | --- |
| 账号ID | Wind Alice 登录账号的内部标识 | 与成员ID分开；同一账号再次加入机构可沿用账号ID，不沿用旧成员ID。页面默认不展示。 |
| 成员ID | 用户加入某机构时生成的成员关系标识 | 每次加入生成新的成员ID，不可修改；用于区分同名成员，并作为机构内席位绑定和历史记录归属的依据。 |
| 所属机构 | 该成员关系归属的机构 | 一个账号同时最多有一个有效的机构成员关系；跨机构查重和归属校验由上游服务支持。 |
| 人名 | 机构为成员维护的姓名 | 可在机构工作台编辑，不修改用户账号本身的展示名称；同名允许存在，以成员ID区分。 |
| 手机号 | 用户登录使用的手机号 | 新增成员时输入，可用于机构搜索；在机构工作台内不可编辑。当前机构已有未移除的同手机号成员时，不允许重复加入。 |
| 邮箱 | 机构维护的成员联系信息 | 新增和编辑时展示；是否必须填写、已有空邮箱如何处理 `[待确认]`。 |
| 加入时间 | 本次加入机构的时间 | 系统记录；移除后重新加入时重新计算，不复用旧时间。 |
| 状态 | 成员在当前机构的访问状态 | 页面显示“启用”“停用”。启用允许访问机构空间及其有权使用的内容；停用仍是机构成员，但不得访问机构相关内容，已占席位保留。 |

“移除”是结束当前成员关系的操作，不作为成员列表的第三种日常状态。移除时释放该关系占用的付费席位；对话、分享下载和积分等历史记录仍归属于原成员ID，不因同手机号再次加入而合并到新成员ID。

### 2.2 席位与订阅

| 字段 | 定义与用途 | 规则 |
| --- | --- | --- |
| 席位编号 | 机构订阅开通的单个付费席位标识 | 固定标识；席位待分配或更换使用人时编号不变。免费版不生成逐席编号。 |
| 订阅订单关联 | 标识席位来自哪笔订阅采购 | 席位需能追溯对应订单；订单及采购数量由企业管理系统管理。订单如何拆分到逐个席位、续费是否沿用编号 `[待确认]`。 |
| 席位类型 | 免费版、基础版、专业版、高级版、尊享版 | 免费版不限量，不进入付费席位库存；其余四种按已采购席位逐席管理。 |
| 剩余积分 | 当前席位可用的积分余额 | 更换使用人或释放时留在席位上，新使用人取得该席位的剩余积分；不转移原使用人的内容和历史记录。余额计算、有效期和跨类型换档结算 `[待确认]`。 |
| 分配状态 | 当前是否已绑定成员 | 已分配、待分配；停用成员持有的席位仍算已分配。 |
| 当前使用人 | 当前绑定该席位的机构成员 | 绑定依据为成员ID，页面可辅助显示人名和手机号；同一成员同时最多持有一个付费席位。 |
| 到期时间 | 当前席位的有效期结束时间 | 由采购或订阅信息提供；续费、提前回收和到期后的处理 `[待确认]`。 |

机构内没有付费席位绑定的成员按免费版使用。席位分配或更换使用人时，只可选择当前机构已启用、尚未持有付费席位的成员；不能因为新操作自动顶替他人已有席位。购买席位的数量或类型与“将已有席位分给谁”是两种不同的业务操作。

### 2.3 使用记录

| 记录 | 本期页面字段 | 关联口径 |
| --- | --- | --- |
| 对话内容 | 时间、成员ID、人名、输入内容、输出内容、文件列表、操作 | 按单一成员ID查询，不把账号再次加入后的新旧成员记录混合。当前原型仍显示“用户 ID”，需在后续同步。 |
| 分享链接 | 时间、成员ID、人名、分享类型、分享链接 | 分享类型包含 Link 看板、Chat 对话、单文件；历史人名取对应成员关系。当前原型仍显示“用户ID”，需在后续同步。 |
| 文件下载 | 时间、成员ID、人名、链接 | 历史记录关联产生时的成员ID。当前原型仍显示“用户ID”，需在后续同步。 |
| 积分记录 | 时间、成员ID、类型、描述、数量 | 记录对应成员的积分事件；席位余额变化如何逐笔对账 `[待确认]`。当前原型仍显示“用户 ID”，需在后续同步。 |

## 3. 页面与功能规划

工作台延续现有页面结构：左侧显示当前机构、功能菜单和左下角用户入口；顶部导航栏显示面包屑及页面级操作，不在内容区重复放页面标题。成员与席位页面从概览卡片、搜索筛选、列表依次展开；记录页面从查询条件和结果列表展开。

### 3.1 成员管理

概览显示成员总数、启用人数和停用人数；列表建议显示成员ID、人名、手机号、邮箱、加入时间、状态和操作。搜索支持人名、手机号、邮箱，并可按状态筛选。成员行提供编辑、启用或停用、移除；手机号只读。停用不释放席位，移除释放席位且保留原成员关系的历史记录。

新增成员的目标表单为人名、手机号、邮箱和席位选择，默认免费版。选择付费版时只能使用尚未分配的席位，并应让管理员能辨认具体席位编号、剩余积分和到期时间；如果最终只按席位类型选择，具体席位的自动挑选规则 `[待确认]`。新增成功后生成成员ID和加入时间，并将所选席位绑定到该成员ID。当前原型只支持新增基础资料，尚未在新增流程内选择席位。

批量添加的目标是上传 Excel，按文件中的成员顺序添加。每行拟包含人名、手机号、邮箱和期望席位类型；目标类型无可用席位时，该成员按免费版加入。批量功能尚未制作；文件列规范、同类型多个席位的分配顺序、重复或无效行的处理、是否允许部分成功，以及导入结果反馈方式均 `[待确认]`。不能把“按序添加”直接等同于“按席位编号顺序分配”。

### 3.2 席位管理

顶部“发起席位调整”用于表达机构希望调整采购席位数量或类型。点击后仅提示“请发起席位调整工单或联系销售”；本期不在工作台内提交工单、改订单或直接改变采购库存。页面仍管理已经购买的席位：概览展示未绑定付费席位的成员，以及基础版、专业版、高级版、尊享版各自的已分配数、总数和未分配数。

点击类型卡片筛选对应类型席位，点击卡片内的未分配席位数进一步筛出待分配席位。逐席列表显示席位编号、席位类型、剩余积分、分配状态、当前使用人和到期时间，并提供分配、更换使用人、释放操作。更换使用人保留席位编号和余额；释放后席位变为待分配，余额仍留在席位上。若同一成员的旧演示数据意外绑定多个席位，原型提示人工核对，不自动决定释放哪一席。

### 3.3 对话内容

查询区只有一个可搜索的成员选择框，聚焦时展示可滚动成员列表；输入人名、手机号或邮箱可筛选候选项。必须选中一名成员才展示对话，不能查询全机构混合明细。时间采用平铺的近1日、近7日、近1月、自定义，默认近7日；自定义使用起止日期。列表展示该成员在所选时间内的记录，点击“查看详情”在右侧查看完整问答和文件。

### 3.4 分享链接、文件下载与积分记录

分享链接和文件下载分别为独立页面，不合并为页内标签。分享链接记录时间、成员ID、人名、分享类型和分享链接；文件下载记录时间、成员ID、人名和链接。积分记录展示时间、成员ID、类型、描述和数量。以上页面当前原型的列名仍为“用户ID”，需与本文件的成员身份口径统一。记录内容的查看权限、保留期限和敏感信息展示 `[待确认]`。

## 4. 已确认规则与待决问题

| 主题 | 当前结论 |
| --- | --- |
| 成员关系 | 手机号对应的当前机构有效关系不可重复；移除后重新加入生成新成员ID。一个账号同时最多加入一个机构。 |
| 成员状态 | 停用阻断机构访问但保留席位；移除释放席位并保留旧关系历史。 |
| 席位数量 | 免费版不限量；每名成员同时最多持有一个付费席位。 |
| 席位余额 | 余额随席位保留，换人不转移原成员内容。 |
| 席位调整 | 采购数量或类型的调整需通过工单或联系销售；当前工作台仅提示办理方式。 |
| 本期展示 | 当前六个页面，不含组织树、节点管理、对话汇总或企业订单页面。 |

影响后续实施的主要待决问题：

1. 邮箱“必要”是否等同新增必填，以及已有空邮箱成员如何处理。
2. 手机号唯一范围与账号归属校验在全平台如何执行；机构工作台原型目前只检查当前机构有效关系。
3. 单个新增选择具体席位，还是只选席位类型并自动挑选；批量导入同类型席位的挑选顺序、异常行和部分成功规则。
4. 席位与订阅订单明细如何关联；续费、换档、到期和积分结算的规则。
5. 节点 Admin 是否参与本期，以及对成员内容和使用记录的可见范围。
6. 成员停用后已有会话、已生成分享链接的访问失效时点，以及内容记录的保留和脱敏规则。

## 5. 当前原型与文档口径

可评审的[机构工作台本期原型](../../原型/机构工作台_本期.html)已经具备六个页面、席位逐席管理、单成员对话查询和“发起席位调整”的提示弹窗。尚未实现成员ID在列表中的展示、使用记录列名统一、成员新增时选席位，以及 Excel 批量导入。这些是后续原型修改项，不应误认为当前页面已提供。

[本期功能范围](16_本期功能范围_2026-10-14.md)与[本期页面决策](17_本期原型页面决策.md)记录上一轮页面和交互决定；[产品边界与术语定义](14_产品边界与术语定义.md)说明企业管理系统与机构工作台的区别。本文在字段名称和新增需求上采用最近讨论的口径；涉及 `[待确认]` 的规则仍需单独决定。
